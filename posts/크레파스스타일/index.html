최근 클로드를 가지고 javascript로 canvas에 그림을 그리는 여러가지 방식을 만들어보고 있었는데 인스타 릴스에서 도로 교통 장면을 애프터이펙트로 크레파스처럼 그린 영상을 보았다. 이걸 canvas로 직접 구현해보고 싶어졌다.

결과물부터 먼저 보면 다음과 같다. 마우스를 움직이면 (모바일은 손가락으로 쓱쓱 그으면) 비둘기가 따라간다.

에셋을 만들어두기 위해 처음에 잠깐 로딩이 있다.

같은 링크에 업데이트했어요. 규칙적으로 보인 건 노이즈 탓이 맞았고, 원인은 이 다섯 가지였어요.

  • 격자 노이즈: value noise의 모든 옥타브가 픽셀 격자와 같은 방향으로 정렬돼 있어서 네모난 뭉침이 반복됐어요.
  • sin 함수: 압력, 굵기, 흔들림을 sin으로 줘서 일정한 주기의 구슬 무늬가 생겼어요.
  • 고정된 크레파스 끝: 끝의 단면을 표 하나로 고정해서, 한 획 내내 줄무늬가 똑같았어요.
  • 균일한 간격: 지그재그 간격이 일정했어요.
  • 같은 구멍: 모든 획이 같은 종이결을 읽어서 겹쳐 칠해도 같은 자리만 비었어요.

검색에서 찾은 것 중 직접 반영한 건 이래요.

크레파스 시뮬레이션 논문 (Rudolf·Mould·Neufeld, 2003): 종이를 높이맵으로, 크레파스를 종이와 닿으면서 변하는 2D 마스크로 표현하고, 왁스가 묻는 양을 접촉 형태, 누르는 힘, 마찰로 계산해요. 여기서 세 가지를 가져왔어요.

  • 종이결: 균일한 화이트 노이즈에 사분원 호를 컨볼루션한 “lunar” 텍스처로 바꿔서 격자 느낌을 없앴어요.
  • 마찰: 크레파스가 종이의 볼록한 부분을 만날 때 왁스를 남긴다는 점을 반영해, 진행 방향을 마주 보는 경사면에 더 묻게 했어요. 획 방향마다 빈 자리가 달라져요.
  • 먼지 자국: 논문은 먼지나 딱딱한 왁스 조각이 획에 점과 줄을 남기는 현상은 다루지 않았다고 했는데, 가끔 흰 줄이 생기게 따로 넣었어요. 크레파스 끝 단면도 획을 따라 서서히 변하게 바꿨어요.

Corel Painter: 반복 없는 자연스러운 자국을 위해 찍을 때마다 종이결 위치를 무작위로 바꾸거나 획마다 회전시키는 옵션이 있어요. 그래서 획마다 어긋난 종이결을 일부 섞었어요.

2. 레퍼런스 선택 주의점

그런데 함정이 하나 있었다. 레퍼런스는 내가 릴스를 캡쳐한 것이라 내 눈에는 크레파스 느낌이 살아있지만 확대해서 캡쳐하다 보니 클로드가 이걸 수치로 분석할때는 뿌옇고 흐린 그림으로 인지하게 된다.

내가 이 상태로 맞춰달라고 했으니 확대된 흐린 상태 그대로 충실하게? 적용이 되었다.

User. 레퍼런스에 맞춰서 개선해줘

🤖 Claude:

레퍼런스 측정값을 목표로 잡고 진행할게요. 목표는 중간톤 0.65 이상, 큰 얼룩 비중 0.6 이상, 선명도 0.15 이하, 결 방향성 0.55 이상이에요. 이걸 맞추려고 바꿀 건 네 가지예요.

  • 연속 톤: 묻는 양을 이분법이 아니라 누르는 힘에 비례해 연속적으로 쌓이게 해요.
  • 큰 얼룩: 획마다 압력을 크게 다르게 주고, 간격을 넓혀서 획 단위 띠가 보이게 해요.
  • 결 방향: 크레파스 끝의 줄무늬를 강하게, 그리고 획을 따라 천천히 변하게 해요.
  • 부드러움: 낮은 해상도로 계산한 뒤 부드럽게 확대해서 보여줘요.

User. 미안하다 왜나하면 내가 캡쳐한것은 확대한것을 캡쳐한거라 뿌얘진거야 그걸 비교히라고 했으니 이건 내 잘못이야 결 방향설? 이런거만 보정하면 될까?

🤖 Claude:

괜찮아요. 확대 캡처인지 확인하지 않고 그대로 목표치로 쓴 제 책임도 있어요.

그래서 확인 실험을 하나 해봤어요. 블러를 넣기 전 버전(v3) 렌더에 확대 캡처와 비슷한 조건(3배 확대 + 블러)을 씌우고 다시 측정했어요.

지표 v3 원본 v3 확대+블러 레퍼런스
중간톤 0.07 0.25 0.75
큰 얼룩 0.36 0.44 0.62
선명도 0.47 0.13 0.15
결 방향성 0.25 0.62 0.56

결과는 예상과 반대였어요. 결 방향성은 확대 블러만 씌워도 레퍼런스 수준까지 올라가요. 블러가 잔 알갱이를 지우면 긴 획 구조만 남기 때문이에요. 선명도도 마찬가지로 블러 때문이었어요. 반면 중간톤과 큰 얼룩은 블러를 씌워도 여전히 차이가 커요. 이 둘이 진짜 차이예요.

그래서 결 방향성만 보정할 게 아니라, 이렇게 정리하는 게 맞아 보여요.

  • 유지: v4의 연속 톤 증착, 획마다 다른 압력, 덧칠 패스. 진짜 차이였던 중간톤과 큰 얼룩을 겨냥한 변경이라 그대로 둬요.
  • 되돌림: 블러와 저해상도 확대. 확대 캡처의 흐림을 따라 한 거라서, 빼고 종이결이 다시 또렷하게 보이게 해요.
  • 측정 방식: 앞으로는 레퍼런스와 같은 캡처 조건을 제 렌더에도 씌운 다음 비교할게요.

한 가지 한계가 있어요. 실제로 몇 배 확대했는지 모르니 “3배"는 추정이에요. 확대하지 않은 캡처를 한 장 주시면 그걸 기준으로 다시 재고 진행할게요.

즉 내눈으로 보정된? 캡쳐화면을 그대로 믿으면 되는것이 아니다. 이는 언급을 하거나 혹은 캡쳐를 할때 본 해상도로 맞춰서 해야하는 부분이다. 꼭 이 작업 뿐 아니라 다른작업 시에도 항상 기억해야 하는 부분인 것 같다.

3. 크레파스 제작 방식

크레파스 스타일은 대략 세 단계로 진행된다.

  1. 계획 : 선이 어디로 지나갈지 정한다. 색칠은 지그재그, 외곽선은 살짝 휘고 떨려서 실수가 잦은 아이의 색칠을 흉내낸다.
  2. 묻히기 : 닳은 크레파스 끝을 그 경로를 따라 문지르며 종이 결에 왁스가 얼마나 걸리는지 픽셀마다 계산한다.
  3. 보여주기 : 결과를 조금씩 흔들어서(boil) 손그림 애니메이션처럼 보여준다.

핵심은 2번이다.

  2. 묻히기 (픽셀): 그 경로를 따라 크레파스 면을 찍으면서, 픽셀마다 왁스가 얼마나 묻는지 계산해요.

1. 종이 (buildPaper)

종이 돌기 높이맵 heq(0-1)를 미리 만들어요. 화이트 노이즈에 사분원 호를 컨볼루션한 “lunar” 텍스처가 기본이에요. 여기에 회전시킨 큰 노이즈 두 겹을 더하고, 히스토그램 평활화로 0-1에 고르게 펴요. 기울기 GX, GY는 마찰 계산에 써요.

2. 계획 (fill, zigzagVerts)

도형을 원하는 각도로 돌린 뒤, 스캔라인과 만나는 양 끝점을 좌우 번갈아 이어 지그재그를 만들어요. 간격은 불규칙하고, 끝점은 경계에서 살짝 모자라거나 넘쳐요. fill()은 두 겹을 돌려줘요. 두 번째 겹은 각도를 10~20° 틀고, 더 듬성듬성하고, 더 가볍게 칠해요. 지그재그가 꺾이는 위치(turns)는 “새로 한 번 지나가는 패스"의 시작점으로 기록해둬요.

3. 묻히기: stamp (가장 중요한 부분)

픽셀 하나에서 일어나는 일은 세 줄로 요약돼요.

JS
const P   = q * (1 - xr*xr) * (rk0 + rk*row[bi]);   // 누르는 힘 × 단면 × 끝의 결
const res = (1 - h)*tau - fk*(GX[i]*tx + GY[i]*ty); // 종이 저항
let c = clamp((P - res) * gain);                     // 접촉량
  • P (누르는 힘): 획 중심에서 가장 세요. 크레파스 끝의 닳은 결(row)이 지나가는 줄에서는 약해져서 줄무늬가 생겨요.
  • res (종이 저항): 돌기 골짜기일수록 커요. 진행 방향을 마주 보는 경사면에서는 작아져요(마찰로 왁스가 걸리는 효과).
  • c (접촉량): 힘이 저항을 넘는 만큼 묻어요. 흰 알갱이는 여기서 생겨요.

가장자리 번짐을 없앤 평균 처리

JS
if (MG[i] !== gen) { MG[i]=gen; M[i]=0; MS[i]=0; MC[i]=0; }
MS[i] += c; MC[i]++;                       // 이번 패스의 접촉 합과 횟수
const target = 1 - Math.exp(-kp * MS[i] / MC[i]);

한 패스 안에서는 찍힌 횟수만큼 쌓지 않고 접촉의 평균을 써요. 그래서 덜 찍히는 가장자리와 끝이 에어브러시처럼 옅어지지 않아요. 지그재그가 꺾이면 gen이 바뀌고, 새 패스는 그 위에 쌓여요.

납작한 끝

JS
const pu = (dx*cph + dy*sph)/a, pv = (dy*cph - dx*sph)/b;
if (pu**4 + pv**4 > 1) continue;               // 둥근 사각형 안쪽만
const he = Math.sqrt(a*a*cn*cn + b*b*sn*sn);   // 이 방향 획의 반폭

닿는 면은 손 각도(HAND)에 고정된 둥근 사각형이에요. 획의 굵기 he는 그 면을 진행 방향의 수직으로 잰 폭이라서, 그리는 방향에 따라 달라지고 획 끝도 비스듬하게 잘려요.

4. 획 따라가기 (advance)

0.6px마다 한 번씩 찍으면서 다섯 가지를 바꿔줘요.

  • 손 떨림: 경로에서 살짝 벗어나요.
  • 끝의 결: row가 획을 따라 아주 천천히 변해서, 줄무늬가 생겼다 흐려졌다 해요.
  • 먼지 자국: 가끔 흰 줄이 지나가요.
  • 압력: 칠할 때는 패스마다 크게 바뀌어서 진하고 연한 띠가 생겨요. 외곽선에서는 선을 따라 서서히 바뀌어요.
  • 시작과 끝: 눌러 들어갔다가 힘을 빼며 떼요.

5. 출력 (present)

미리 만든 떨림 맵 3장 중 하나로 픽셀을 1~2px 밀어서 복사해요. AE의 Turbulent Displace + Posterize Time과 같은 역할이에요.

조절 손잡이

느낌을 바꿀 때 주로 만지는 값이에요.

값 역할 칠하기 / 외곽선
tau 종이 저항. 높을수록 알갱이가 많아요 0.25 / 0.56
ridgeK 끝의 결(줄무늬) 세기 0.6 / 0.55
kPass 한 번 지날 때 진하기 3.4·2.4 / 3.8
resist 이미 칠한 색 위에 덧칠할 때의 저항 0.7 / 0.15
pa, pb 납작한 면의 장축·단축 비율 1.15·0.55 / 1.1·0.7

데모는 같은 로직을 한 파일 안에 그대로 넣어둔 상태라서, 스킬로 만드실 때는 crayon-core.js 쪽을 기준으로 쓰시면 돼요.

위 설명은 0.6px마다 크레파스 면을 찍는 방식(stamp)인데 실제 비둘기 데모는 sweep 모드로 돌린다. 찍는 방식은 한 번 지나갈 때 픽셀 하나를 30번 넘게 계산하지만 sweep은 경로에서 가장 가까운 점을 기준으로 한 번만 계산한다. 모양은 같고 약 8배 빠르다.

4. 비둘기

단순히 도로 교통을 크레파스로 그리는 것 뿐 아니라 마우스 상호작용으로 비둘기를 넣어서 교통체증에 영향을 주도록 했다.

  • 마우스(모바일은 손가락)를 따라 걸으며 고개를 까딱인다. 가만히 있으면 땅을 쪼아댄다.
  • 멀리 떨어지면 날아오르고 가까워지면 내려앉는다.
  • 비둘기가 차 앞을 막으면 차가 멈춘다.
  • 옆이나 뒤에서 다가가면 차가 냅다 달아난다. 이때 차 위에 크레파스로 그린 “!“가 뜬다.

비둘기 모델은 1.6m짜리인데 도로에서는 이걸 1.7배 키워서 그린다. 차가 피할만 하다.

5. 축구장면 만들기

그 외 아들 축구 장면을 크레파스로 그려보면 좋을 것 같은 생각이 들었다. crayon-soccer.vercel.app

6. 후기

최근 클로드를 사용하면서 Canvas를 사용하는 형태를 많이 만들어보고있는데 사용하면서 이런 저런 시행착오를 많이 겪어보고 있다. 마냥 잘 만든다고 의존하는 것이 아니고 사람이 계획을 잘 세워서 좋은 순서로 물어보는것도 중요한 것 같다.

토큰만 낭비하다가 클로드가 리서치를 해서 논문을 찾아 공식을 적용하는 순간부터 퀄리티가 급격하게 올라간 것을 보면 “찾아본거니?(리서치를 해라)” 이게 최종 퀄리티를 결정하는데에 결정적으로 영향을 끼친 것이다.
