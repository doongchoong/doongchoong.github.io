## 2. 동작원리

색을 몇 개로 줄여야 할 때 가장 단순한 방법은 기준값(0.5)보다 밝으면 흰색, 아니면 검은색으로 찍는 것이다.
그런데 이렇게 하면 부드럽던 그라데이션이 몇 개의 평평한 덩어리로 뚝뚝 끊긴다. (밴딩)

디더링의 아이디어는 일부 픽셀을 일부러 **틀린** 색으로 찍되
그 빈도가 원래 밝기에 비례하게 만드는 것이다.
30% 밝기의 영역이라면 대략 10개 중 3개만 흰 점으로 찍히고, 멀리서 보면 회색처럼 보인다.
즉, 눈이 평균을 내는 것이다.

### 2.1. 랜덤

픽셀마다 기준값을 랜덤으로 뽑는다.
가장 쉬운 방법이지만 결과가 지글지글한 노이즈처럼 보이고
점이 우연히 뭉치거나 비는 곳이 생긴다.

### 2.2. Bayer

랜덤 대신 **픽셀 위치에 따라 정해진 기준값**을 쓴다.
기준값을 담은 표가 Bayer 행렬인데, 2×2에서 시작해 재귀적으로 4×4, 8×8로 키운다.

```txt
2×2       4×4
0 2        0  8  2 10
3 1       12  4 14  6
           3 11  1  9
          15  7 13  5      (÷ 행렬 칸 수)
```

이 표를 화면에 타일처럼 깔고, 픽셀 밝기를 해당 칸의 값과 비교한다.
위치만 알면 계산이 끝나서 픽셀끼리 서로 기다릴 필요가 없다.
고로 GPU 셰이더에서 모든 픽셀을 한꺼번에 처리할 수 있다.
미니어처 마을도 3D 장면을 텍스처에 먼저 그린 다음, 화면 전체에 아래 셰이더를 한 번 돌린다.

```glsl
// 2x2 Bayer의 닫힌 식. 이걸 재귀로 쌓으면 4x4, 8x8이 된다.
float bayer2(vec2 a) { a = floor(a); return fract(a.x / 2.0 + a.y * a.y * 0.75); }
float bayer4(vec2 a) { return bayer2(0.5 * a) * 0.25 + bayer2(a); }
float bayer8(vec2 a) { return bayer4(0.5 * a) * 0.25 + bayer2(a); }

float threshold(vec2 p) {
  if (mode == 2) return hash(p);                  // 랜덤
  if (mode == 3) return bayer4(p) + 0.5 / 16.0;   // Bayer 4x4
  if (mode == 4) return bayer8(p) + 0.5 / 64.0;   // Bayer 8x8
  return 0.5;                                     // 고정 임계값
}

void main() {
  vec3 x = texture2D(tex, vUv).rgb;
  float t = threshold(gl_FragCoord.xy);
  float L = levels - 1.0;
  vec3 q = floor(x * L + t) / L;                  // 채널마다 levels 단계로 양자화
  gl_FragColor = vec4(q, 1.0);
}
```

`floor(x * L + t)`에서 `t`가 기준값 역할을 한다.
`t`가 0.5로 고정이면 그냥 반올림이고, 위치마다 달라지면 디더링이 된다.
단계(`levels`)를 2로 두면 흑백 두 색, 4로 두면 채널마다 네 단계가 된다.

### 2.3. 주의점: Bayer 편향 보정

코드에서 `+ 0.5 / 16.0` 부분이 Bayer의 편향 보정이다.

Bayer 행렬 값은 `0/16 ~ 15/16`이라 평균이 0.5보다 살짝 작다.
그래서 행렬 값을 그대로 쓰면 전체 밝기가 한쪽으로 치우치는데
흔히 쓰는 `밝기 > 행렬값` 비교라면 흰 점이 더 찍혀서 원본보다 밝아지고
위 코드처럼 더하는 방식이라면 반대로 살짝 어두워진다.
특히 단계가 적을수록 티가 많이 난다.

그래서 칸 크기의 절반(`0.5 / 칸 수`)을 더해 평균을 정확히 0.5에 맞춘다.
이렇게 해야 디더링 전과 후의 평균 밝기가 같아진다.

## 알고리즘은 세 갈래
| 갈래 | 방식 | 특징 |
|---|---|---|
| **랜덤** | 임계값 비교 전에 노이즈를 더함 | 거칠고, 점이 뭉치거나 비는 곳이 생김 |
| **정렬(ordered)** | 임계값을 픽셀 위치에 따라 바꿈(Bayer 행렬) | 점 연산이라 GPU에서 빠르고, 애니메이션에 안정적임. 격자 무늬가 눈에 띔 |
| **오차 확산** | 양자화 후 남은 오차를 이웃 픽셀에 나눠 줌 | 톤 재현이 좋고 엣지가 살아남. 순차 처리라 병렬화가 어렵고, 움직이면 흔들림 |

**Bayer 행렬**은 2×2 `[0 2; 3 1]/4`에서 재귀적으로 키워 갑니다.

**오차 확산 커널**(`*`은 현재 픽셀)은 다음과 같습니다.
- **Floyd–Steinberg**: `* 7 / 3 5 1`을 16으로 나눕니다.
- **Atkinson**: 이웃 6곳에 각 1/8씩 줍니다. 합이 6/8이라 오차의 1/4를 일부러 버립니다. 그래서 하이라이트와 섀도가 날아가고 대비가 센, 초기 Mac 특유의 룩이 나옵니다.
- **Jarvis–Judice–Ninke**(12탭, ÷48)와 **Stucki**(12탭, ÷42)는 커널이 큽니다. 더 부드럽지만 느리고 덜 선명합니다.

## 현대 기법
- **블루노이즈 임계값 맵**은 고주파만 있고 저주파 패턴이 없어서 가장 덜 거슬립니다. void-and-cluster 알고리즘으로 생성합니다.
- **Interleaved Gradient Noise**는 텍스처 없이 수식 한 줄로 블루노이즈 비슷한 값을 냅니다: `fract(52.9829189 * fract(dot(p, vec2(0.06711056, 0.00583715))))`. 실시간 렌더링에서 밴딩 제거용으로 씁니다.
- **Return of the Obra Dinn**은 3D를 1비트로 렌더링하면서 Bayer와 블루노이즈를 병용했습니다. 움직일 때 패턴이 흔들리는 문제 때문에 카메라 회전에 맞춰 패턴을 오프셋하는 등 여러 방법을 시도했습니다.

대략 감이 잡혔다. 크게 보면 기준값을 바꾸는쪽(랜덤, Bayer, 블루노이즈)과
오차를 이웃에게 떠넘기는 쪽(Floyd–Steinberg, Atkinson, Jarvis–Judice–Ninke)으로 나뉜다.

오차 확산은 앞 픽셀의 오차를 받아야 다음 픽셀을 계산할 수 있어서 순서대로 처리해야 한다.
정지된 그림 한 장이라면 톤이 가장 정확하게 나오지만
매 프레임 움직이는 3D 장면에서는 쓰기 어렵다.
미니어처 마을은 위치만으로 계산이 끝나는 Bayer를 골랐다.

Atkinson이 오차의 1/4를 일부러 버린다는 점이 재미있다.
정확함을 조금 포기하고 대비를 얻었다고 하며,
초기 맥킨토시 느낌이라고 한다.

같은 그라데이션에 방법별로 흑백 두 색 디더링 적용된것은 아래와 같다.

<script>
(function () {
  var W = 240, H = 18;
  // 화면에 보이는 그라데이션(sRGB)을 빛의 양(선형)으로 바꿔 디더링해야 멀리서 본 밝기가 원본과 맞는다
  function toLin(c) { return c <= 0.04045 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4); }
  function bayer(n) {
    var m = [[0]];
    for (var s = 1; s < n; s *= 2) {
      var next = [];
      for (var y = 0; y < s * 2; y++) {
        next.push([]);
        for (var x = 0; x < s * 2; x++) next[y].push(4 * m[y % s][x % s] + [0, 2, 3, 1][(y >= s ? 2 : 0) + (x >= s ? 1 : 0)]);
      }
      m = next;
    }
    return m;
  }
  var B4 = bayer(4), B8 = bayer(8);
  function ordered(th) {
    return function (v) {
      var out = new Uint8Array(W * H);
      for (var y = 0; y < H; y++) for (var x = 0; x < W; x++) out[y * W + x] = v[y * W + x] > th(x, y) ? 1 : 0;
      return out;
    };
  }
  // [dx, dy, 가중치] 목록으로 오차를 이웃에게 나눠 준다
  function diffuse(kernel) {
    return function (v) {
      var buf = Float32Array.from(v), out = new Uint8Array(W * H);
      for (var y = 0; y < H; y++) for (var x = 0; x < W; x++) {
        var i = y * W + x, q = buf[i] > 0.5 ? 1 : 0, e = buf[i] - q;
        out[i] = q;
        for (var k = 0; k < kernel.length; k++) {
          var nx = x + kernel[k][0], ny = y + kernel[k][1];
          if (nx >= 0 && nx < W && ny < H) buf[ny * W + nx] += e * kernel[k][2];
        }
      }
      return out;
    };
  }
  var JJN = [[1,0,7],[2,0,5],[-2,1,3],[-1,1,5],[0,1,7],[1,1,5],[2,1,3],[-2,2,1],[-1,2,3],[0,2,5],[1,2,3],[2,2,1]]
    .map(function (k) { return [k[0], k[1], k[2] / 48]; });
  var METHODS = [
    ['원본', null],
    ['고정 임계값', ordered(function () { return 0.5; })],
    ['랜덤', ordered(function () { return Math.random(); })],
    ['Bayer 4×4', ordered(function (x, y) { return (B4[y & 3][x & 3] + 0.5) / 16; })],
    ['Bayer 8×8', ordered(function (x, y) { return (B8[y & 7][x & 7] + 0.5) / 64; })],
    ['IGN', ordered(function (x, y) { var t = 0.06711056 * x + 0.00583715 * y; t -= Math.floor(t); t *= 52.9829189; return t - Math.floor(t); })],
    ['Floyd–Steinberg', diffuse([[1, 0, 7 / 16], [-1, 1, 3 / 16], [0, 1, 5 / 16], [1, 1, 1 / 16]])],
    ['Atkinson', diffuse([[1, 0, 1 / 8], [2, 0, 1 / 8], [-1, 1, 1 / 8], [0, 1, 1 / 8], [1, 1, 1 / 8], [0, 2, 1 / 8]])],
    ['Jarvis–Judice–Ninke', diffuse(JJN)]
  ];

  var src = new Float32Array(W * H);
  for (var y = 0; y < H; y++) for (var x = 0; x < W; x++) src[y * W + x] = toLin(x / (W - 1));

  var box = document.getElementById('dg-box');
  METHODS.forEach(function (m) {
    var label = document.createElement('span');
    label.textContent = m[0];
    var cv = document.createElement('canvas');
    cv.width = W; cv.height = H;
    var ctx = cv.getContext('2d'), img = ctx.createImageData(W, H);
    var bits = m[1] ? m[1](src) : null;
    for (var i = 0; i < W * H; i++) {
      var c = bits ? bits[i] * 255 : Math.round((i % W) / (W - 1) * 255);
      img.data[i * 4] = img.data[i * 4 + 1] = img.data[i * 4 + 2] = c;
      img.data[i * 4 + 3] = 255;
    }
    ctx.putImageData(img, 0, 0);
    box.appendChild(label);
    box.appendChild(cv);
  });
})();
</script>

* 고정 임계값은 그라데이션이 그냥 흑백 두 덩어리로 갈린다. (경계가 가운데보다 오른쪽인 건 빛의 양 기준 50%가 화면 밝기로는 70% 쯤이라서)
* 랜덤은 점이 뭉치고 비는 곳이 생겨 지저분하다.
* Bayer는 격자 무늬가 규칙적으로 깔린다. 8×8이 단계가 더 촘촘하다.
* Floyd–Steinberg는 점이 벌레처럼 구불구불 이어지는 무늬가 보인다.
* Atkinson은 어두운 쪽은 까맣게, 밝은 쪽은 하얗게 일찍 날아간다. 가운데만 디더링되는 느낌.
* Jarvis–Judice–Ninke는 오차를 넓게 퍼지게해서  그런지 가장 고르게 섞인다.

## 4. 후기

디더링은 참 신기하다.
색이 몇 개 없는데도 없는 색을 보이게 해주고
색을 줄이면서 생기는 밴딩 같은 시각적 결함을 보상해 준다.

요즘은 색이 부족할 일이 거의 없는데도
레트로 느낌을 내거나 옛 추억을 떠올리게 하려고 일부러 디더링을 쓰기도 한다.

기술적으로도, 문화적으로도 참 괜찮은 "도구"인 것 같다.
